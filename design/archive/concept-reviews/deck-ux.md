## 공통 (세 안 모두)
- **[3] A로 고르기 → 포커스가 "빼기"로 이동 → 다시 A = 확정** (A `remove-confirm`, B `f2-rm-*-ok`, C `f2-cf-ok`). 같은 버튼을 두 번 누르면 되돌릴 수 없는 제거가 끝나요. 패드 연타·더블 클릭 한 번으로 잘못된 카드가 빠질 수 있어요 (NN-5 오류 예방, SD-CTL). → 고른 뒤 포커스는 카드에 남기고 "빼기"로는 방향 입력으로 옮기게 하거나, 확정을 길게 누르기 같은 다른 입력으로 분리. 확정 직후 짧은 "되돌리기"는 기획 판단.
- **[2] 한 화면에 B 라벨이 두 개** — 머리의 닫기/그만두기 버튼과 확인 줄의 "다시 고르기"가 동시에 B로 표시돼요. 지금 B가 무엇을 하는지 상태에 따라 달라지는데 화면은 둘 다 보여 줘요 (NN-1 상태 가시성). → 확인 대기 중에는 머리 버튼의 B 표시를 숨기거나 흐리게 하고, B 표시는 지금 B가 실제로 하는 쪽 하나에만.
- 휴식 제거의 대가가 안마다 달라요 (A·C "쉬기 대신", B "비용 없음"). UX 문제는 아니고 기획 질문이에요. 세 안 모두 "어디서 열었는지" 문구는 잘 들어가 있어요.

## A · 정령별 세 줄
1. **[3] `view-row-fire` 외 각 줄 (`remove-row-*`)** — 한 줄에 카드가 약 10장까지 들어가요. 제거 모드는 묶기를 풀어 펼치므로 frame2의 이그니 줄(9장)이 이미 거의 꽉 찼어요. 덱이 30장대로 크면 한 정령이 12장을 넘기 쉽고, 줄 가로 스크롤이 생기면 줄 밖 카드가 보이지 않는 채로 제거를 판단하게 돼요 (NN-1 상태 가시성, 브리프 "꽉 찬 상황"). 페이지 스스로도 "포기하는 것"에 적었어요. → 줄이 넘치면 그 줄만 두 줄로 접어 내리는 규칙(줄 높이 가변 + 레이어 세로 스크롤)을 정하고, 가로 스크롤은 쓰지 않기.
2. **[2] `remove-lclose` ("뒤로 Esc · B")** — 컨트롤러 메모상 확인 대기 중 B는 "고르기 취소"인데, 그 순간 B가 붙은 버튼은 "뒤로"예요. 실제 B 동작을 하는 `remove-cancel` ("고르기 취소")에는 B 표시가 없어요 (NN-4 일관성). → B 표시를 상태에 따라 `remove-cancel` 쪽으로 옮기기 (공통 2와 같은 처리).
3. **[2] `view-sort` (배운 순서·비용·종류)** — 정렬이 줄 안에서만 적용돼, "비용 3 카드가 덱에 몇 장인가"처럼 덱 전체를 가로지르는 질문은 세 줄을 각각 훑어야 답할 수 있어요 (NN-7 효율). 상점·제거에서 비용 곡선을 볼 때 쓰는 질문이에요. → 정렬은 줄 안 그대로 두되, 정렬 기준의 묶음 경계(비용 1 | 2 | 3)를 각 줄에서 같은 세로 위치로 맞추거나, "전체 섞어 보기" 한 가지를 추가.
4. **[1] `detail-dt-*` (큰 카드)** — 누른 카드 위에 붙어 펼쳐지는 방식이라 보상·상점(카드가 줄로 놓이지 않는 화면)에서는 붙일 기준이 달라져요. 메모 detail-memo2가 덱 보기 기준만 정의해요. → 큰 카드 + 옆 판의 위치 규칙을 "기준 카드가 있을 때 / 없을 때(화면 가운데)" 두 가지로 적어 두기.
- 잘된 점: 줄 머리의 파워·가드 → 카드 ▲▼ → 큰 카드 계산 줄이 한 화면에서 이어져 결과 예측이 쉬워요. 확인 줄이 카드 이름·주인·"탐험이 끝날 때까지 되돌릴 수 없어요"를 모두 말해요 (`remove-cq`). 제거 모드에서 자동으로 펼쳐 어느 한 장을 빼는지 분명해요.

## B · 한 장의 그리드
1. **[3] `f2-pan` + `f2-rm-*-ok` (패널의 "1장 빼기")** — 컨트롤러 메모(f2-pad): 고른 뒤 방향키로 다른 카드에 가면 "고른 표시는 그대로, 패널은 포커스 카드 미리보기". 그런데 확인 버튼이 카드마다 패널 안에 따로 있어(`f2-rm-fspark-ok`, `f2-rm-claw-ok`…) 미리보기 중인 카드의 버튼이 뜨고, 문구도 "이 카드 1장을 덱에서 뺄까요?"예요. 자두빛 테(고른 카드)와 패널(보는 카드)이 서로 다른 카드를 가리키는 순간 무엇이 빠지는지 모호해요 (NN-5, PIN 결과 예측). → 확인 줄은 고른 카드에만 묶고 미리보기와 분리(미리보기 중엔 확인 버튼 대신 "이 카드로 바꾸기 A"), 확인 문구에 "이 카드" 대신 카드 이름을 넣기.
2. **[2] `f1-grid` → `f3-grid` (8열 → 6열)** — 패널이 열리면 그리드가 다시 흘러서 카드 위치가 바뀌어요. 패드로 이동하던 칸 기억이 깨지고, 묶기를 끄면 고른 카드가 화면 아래로 잘려 나가요 (x-f1-unstack.png에서 고른 "물결 장막"이 잘림, 스크롤 표시 없음) (NN-6 기억 부담, SD-CTL). → 열 수는 패널 여부와 상관없이 고정하거나, 패널이 열릴 때 포커스 카드를 화면 안으로 스크롤해 붙이고 아래에 더 있다는 표시를 두기.
3. **[2] `f1-grid` (정렬 "주인")** — 주인 순으로 놓아도 정령 사이 경계가 없어서, 실바 카드가 어디서 끝나는지는 카드의 작은 얼굴 홈으로만 읽혀요. 정령이 셋인 지금은 읽히지만 정령이 늘거나 비슷한 얼굴이 생기면 어렵고, 제거에서 "이 정령이 몇 장 남는가"를 볼 때 손으로 세야 해요 (NN-6). → 정렬이 "주인"일 때만 정령 경계(구분선 또는 줄바꿈)를 넣고 장수를 경계에 표시.
4. **[1] `f1-lt` 머리의 "지도에서 열었어요"** — 잘 들어갔어요. 다만 전투에서 열 때 패널이 오른쪽 1/3을 덮으면 필드 상태(받을 피해 합계)가 가려지는지 확인이 필요해요. → 전투에서 연 경우의 프레임 1장(어디가 비치는지)을 다음 라운드에 추가.
- 잘된 점: 보기·제거·큰 카드가 한 레이어, 바뀌는 건 머리 문구와 패널 아래 버튼뿐이라 보상("고르기")·상점("사기") 재사용이 셋 중 가장 쉬워요. LB/RB/Y/X 바로가기와 화면 아래 버튼 안내가 프레임에 상시 보이고(SD-CTL), 포커스(점선)와 선택(실선)이 모양으로 갈려요(장부 5번 반영). 제거에서 묶음을 유지해 "불똥 튀기기 2 → 1"로 보여 주는 것도 명확해요.

## C · 정령과 함께 보는 덱
1. **[2] `f2-cf` (확인 줄)** — "불꽃 할퀴기 1장을 덱에서 뺄까요? 이그니 7 → 6 · 덱 24 → 23"까지는 좋은데, 되돌릴 수 없다는 말이 없어요 (A의 `remove-cq`에는 있음). 또 왼쪽 그림·이름 카드·얼굴 띠·확인 줄 네 곳이 동시에 7 → 6을 말해 시선이 흩어지고, 정작 확정 버튼(`f2-cf-ok`)은 화면 오른쪽 아래 끝이에요 (NN-5, PIN 읽는 순서). → 확인 줄에 되돌릴 수 없음 한 줄 추가, 변화 표시는 확인 줄과 얼굴 띠 두 곳으로 줄이기.
2. **[2] `f1-dsc` / `f3-dsc` (포커스 = 큰 카드 상세)** — 포커스만 옮겨도 카드가 커지고 설명이 옆에 붙어, 패드로 격자를 훑는 동안 매 칸마다 옆 카드 2~3장이 가려져요 (frame3에서 산들 바람·유성우·늦은 별빛이 가려짐). 브리프의 "큰 카드 + 전체 설명"보다 작아서 보상·상점에서 "고르기/사기" 버튼을 붙일 자리도 없어요 (PIN 가시성, 재사용). → 포커스 = 짧은 말풍선(전투 H1), A/클릭 = 큰 카드 상세로 두 단계를 나누기 (A·B와 같은 구조).
3. **[2] `f2-mode` / 얼굴 띠 `f2-t-fire`** — frame2는 한 정령(이그니)만 보이는 상태에서 제거해요. 다른 정령 카드와 견주려면 LB/RB로 띠를 돌려야 하고, 돌릴 때 왼쪽 그림·능력치가 통째로 바뀌어 비교 대상이 화면에서 사라져요 (NN-6 기억 부담). → 제거 모드의 기본 보기를 "전체"로 열고, 정령 하나 보기는 선택으로.
4. **[2] `f1-arts` / `f1-aall-tiles`** — "전체" 보기에서 왼쪽 위 세 정령 그림 타일이 아래 얼굴 띠(`f1-t-*`)와 같은 정보(이름·장수)를 한 번 더 보여 주는데, 누를 수 있는지 아닌지가 화면에서 구분되지 않아요 (NN-4). 왼쪽 그림 자리(약 350px)가 고정이라 덱이 커지면 격자 폭이 먼저 모자라고(한 줄 7장), "전체" 펼침은 세로 스크롤이 필요해요. → "전체"에서는 그림 타일을 빼고 그 폭을 격자에 돌려주기. 그림은 정령 하나 보기에서만.
- 잘된 점: 카드 ↔ 주인 ↔ 능력치(`f1-idc-star-st`)가 한 화면에 있어 "왜 7인지"가 가장 빨리 풀려요. 컨트롤러·B 메모(`sec-ctrl`)가 셋 중 가장 완결돼 있고, "반드시 1장 빼기" 이벤트에서 B를 막는 경우까지 적었어요. "기본" 표시로 시작 카드를 구분하는 것도 제거 판단에 도움이 돼요.

## 체리피킹 제안 (UX 관점만, 고르는 건 Lucy)
뼈대는 **B의 "그리드 + 오른쪽 큰 카드 패널"**이 재사용(보상 고르기·상점 사기·전투 중 열기)과 덱 확장에 가장 강해요. 다만 B의 약점인 "주인 읽기"는 **A의 정령별 줄 머리(장수 · 시작/이번 탐험 · 파워·가드)**를 "주인 정렬"일 때의 경계 머리로 가져오면 메워지고, 비용·종류 정렬일 때는 B처럼 섞어 보면 돼요. 큰 카드 패널의 계산 줄과 "다른 정령이 배우면" 표는 A(frame3, 주인 행 강조 + 차이 ▲)가 가장 읽기 쉬워요. 제거 확인은 **A의 확인 줄 문구(카드 이름 · 주인 · 되돌릴 수 없음)** + **C의 "이그니 7 → 6"을 얼굴 띠에 같이 보여 주기**를 섞고, B의 미리보기/선택 분리를 꼭 고쳐야 해요. 컨트롤러는 **C의 메모(`sec-ctrl`)를 기준 문서로**, B의 화면 아래 버튼 안내를 상시 표시로 쓰고, 세 안 공통인 "A 두 번 = 확정"은 다음 라운드에서 구조를 바꿔야 해요. C의 그림·능력치 이름 카드는 덱 보기보다 정령 관리에서 이미 쓰는 자리라, 덱 보기에서는 "정령 하나 보기"를 고를 때만 보이게 하는 편이 레이어를 가볍게 해요.
