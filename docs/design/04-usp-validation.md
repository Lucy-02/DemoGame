# 04. USP 검증: "누가 배울까" 프로토타입 (S2)

- 상태: 초안 (계획). 결과는 이 문서 아래에 기록해요.
- 검증할 것: 우리 조각 둘 — **같은 카드 다른 손**(보상에서 배울 정령을 고르면 손패 값이 달라짐)과 **배운 카드가 갈래를 연다**(0022)가 플레이어에게 선택으로 느껴지는가.

## 가설
1. H1 보상 화면에서 "어느 정령이 배울까"가 "어느 카드를 고를까"만큼 고민된다 (고민 시간·번복 횟수로 봄).
2. H2 같은 파티·같은 카드 풀로 두 판을 하면 손패 분포가 눈에 띄게 달라진다 (정령별 카드 수 분포).
3. H3 "N장 배우면 갈래가 열린다"를 보여 주면, 플레이어가 조건을 목표로 삼아 배울 정령을 고른다 (조건 쪽으로 기우는 선택 비율).
4. H4 반대 가설: 플레이어는 항상 수치가 큰 정령에게 몰아 준다 → "다른 손"이 선택이 아니라 정답이 됨. 이러면 역할·능력치 폭(0020)을 좁히거나 보상 풀을 손봐야 해요.

## 최소판 (코드 최소)
- 지금 있는 것으로 돌려요: 레거시 화면(`?screen=legacy`)의 보상 3택 + 배울 정령 선택, MVP 3종 데이터.
- 추가 한 가지: 보상 화면에 "이 정령이 배우면 N"을 정령별로 나란히(브리프 3번 요구사항, 이미 레거시에 있는지 확인).
- 갈래 조건 미리보기: 코드 없이 **종이**. 런 시작 전 쪽지에 "불여우: 불 공격 카드 4장 배우면 갈래 A / 바람·무속성 4장이면 갈래 B" 식으로 적어 두고, 런 끝에 어디가 열렸는지 사람이 채점해요. 조건 수치는 `TODO_TOKEN`(첫 판은 4장으로 가정).
- 로그: `pnpm sim`이 아니라 **사람 플레이**예요. 한 판마다 보상 선택(카드·정령·번복 여부·걸린 시간 대략)을 표로.

## 절차
1. Lucy 2~3판 + Claude 자동 플레이 20시드(`tools/sim.ts`, 비교용 분포).
2. 판마다: 정령별 배운 카드 수, 손패에서 "다른 손" 차이를 눈으로 본 순간(있었나), 갈래가 열렸나.
3. 종이 조건이 "목표"로 작동했는지 Lucy 한 줄 소감.

## 판단 기준 (가안)
- H1·H3가 보이면 → 0022 그대로, 성장 길 탭 시안 라운드로.
- H4가 보이면 → 보상 풀에 "같은 속성 2장 + 다른 속성 1장" 같은 규칙을 넣고 재시험, 또는 능력치 폭 조정 제안.
- 자동 플레이 분포가 사람과 크게 다르면 `autoplay.ts`를 개선하지 않고 사람 결과만 믿어요(툴은 밸런스용).
