# R5. 효과 문구(카드·용어 풀이·적 의도·패시브·이벤트 결과) 한국어 작성 규칙

- 범위: 카드 효과문, 용어(키워드·상태) 풀이, 적 의도, 패시브(성격·지속·유물류), 이벤트 선택지 결과의 **한국어 문장 규칙**이에요. 성공작 한국어판의 실제 문구를 모아 어미·어순·숫자 위치·동사·조건·대상·기간·키워드·문장부호·조사 처리를 세고, 우리 효과 전부를 규칙대로 옮겨 봤어요.
- 방법: 한국어 카드 데이터를 공개 API에서 통째로 받아 정규식으로 셌어요(하스스톤 7,425장, 룬테라 279장 + 용어 123개, MTG 156장, 섀도우버스 4,227개 문구). Slay the Spire 1·2와 Balatro는 위키·DB 페이지를 열어 표본을 옮겼어요(StS1 카드 30·유물 25, StS2 카드 79, Balatro 조커 20). 페이지 요약 도구로 옮긴 표본이라 글자 하나 단위 오류가 있을 수 있어요(1장 주석). 정규식 집계는 근사치예요. 셈법은 2장 머리에 적었어요. 열어서 확인하지 못한 주장에는 **[미확인]**을 붙였어요.
- 전제: Lucy가 정한 방향(합니다체, 완결된 문장, 어순 중시, 동사 "입히다")과 용어(피해, 방어도, 화상, 냉기, 빙결, 반격, 성장, 취약, 약화, 강화, 도발, 마력, 싱크로율, 소멸, 앞열, 파워/가드/포커스, 정령, 카드 동사 "사용")는 고정으로 두었어요. 용어 문제는 5장에 **표시만** 했고 이름을 바꾸자는 규칙은 넣지 않았어요. 이 문서는 결정이 아니라 규칙 초안과 근거예요.

## 0. 한눈에 보기

1. **디지털 카드 게임 한국어판은 합니다체가 표준이에요.** 문장 끝을 세면 하스스톤 9,141 : 한다체 0, 룬테라 302 : 0, StS2 130 : 0, StS1 카드 47 : 0이에요. 한다체는 MTG(324 : 합니다 1), 명사로 끊는 문체는 섀도우버스(명사 끝 5,951 · 한다 3,171)뿐이에요. Lucy의 방향이 주류와 같아요.
2. **숫자 자리는 "목적어 + 조사 → 숫자 → 동사"로 거의 굳어 있어요.** `피해를 6 줍니다`(StS), `피해를 2 입힙니다`(룬테라), `방어도를 5 얻습니다`, `취약을 2 부여합니다`. 하스스톤에서 `피해를 N 줍니다` 꼴은 896장, `N의 피해를`은 62장이고 그중 61장은 "무작위로 나누어 입힙니다"처럼 피해를 쪼개는 특수한 효과예요. 이 어순의 숨은 장점은 **숫자 뒤에 조사가 오지 않는다**는 거예요.
3. **피해 동사는 둘로 갈려요.** 하스스톤·StS는 "주다"(하스스톤 1,080장, StS2 43장), 룬테라·MTG는 "입히다"(룬테라 31 : 주다 1)예요. "가하다"는 다섯 게임 어디에도 없어요(0건). Lucy가 고른 "입히다"는 룬테라 쪽 관행이에요. 피해를 받는 쪽을 주어로 쓸 때 "피해를 N 입습니다"(룬테라)로 짝이 맞아요.
4. **조건은 문장 앞, 조건 문장은 기본 효과 문장 뒤에 와요.** 조건이 든 문장이 기본 효과 뒤에 오는 경우가 하스스톤 459 : 앞 47, StS2 8 : 0이에요. 조건절 뒤 쉼표는 하스스톤 860 : 297, 섀도우버스 1,529 : 78, StS2 4 : 0으로 쉼표 쪽이 많아요.
5. **카드 성질은 명사 + 마침표 한 단어 문장이에요.** StS1·StS2 표본에서 `소멸.`은 14번 모두 맨 끝(`휘발성.`도 끝), `선천성.` `교활.` `보존.`은 맨 앞이에요. 합니다체의 유일한 예외로 쓸 만해요.
6. **여러 효과는 효과마다 한 문장이에요.** 같은 대상구를 되풀이해야 할 때만 "~고"로 묶어요(StS2 `모든 적에게 피해를 4 주고 취약을 1 부여합니다.`). 2문장 이하인 카드가 하스스톤 98%, StS2 79장 중 75장이에요.
7. **용어 풀이는 짧은 합니다체 1~2문장이에요.** 룬테라 용어 123개는 120개가 합니다체로 끝나고, 길이 중앙값은 공백 빼고 32자, 1문장이 78개, 2문장이 39개예요.
8. **조사 병기 `을(를)`은 공식 카드 데이터에서 한 번도 안 나와요**(4개 게임 전수 0건). 반면 데이터를 다시 찍어 내는 2차 사이트에는 `약화을(를)`, `힘을(를)`(op.gg StS2 몬스터 페이지)이 보여요. 우리 `text.ts`도 `${d}을 ${hits}번`처럼 숫자 뒤에 "을"을 박아 둬서, 수치가 2·4·5·9가 되면 `2을`처럼 틀려요.
9. **한국어판 불만은 대개 "통일 안 됨"과 "설명이 실제 동작과 다름"이에요.** 나무위키는 StS 한국어에서 조건문이 "더욱 통일성이 떨어지는 편"이라고 적고, 유물 설명 5개를 오역·부정확 사례로 들어요. StS1 유물에서는 `1의 에너지를 얻습니다`와 `체력을 6 회복합니다`가 섞여 있어요(25개 중 "N의" 꼴 5개). Balatro는 공식 번역 품질이 낮아 위키가 팬 수정 모드를 기준으로 서술해요.
10. 규칙대로 옮기면 **카드 문구가 평균 2.1배 길어져요**(우리 40장, 공백 제외 중앙값 8자 → 19.5자, 최장 21자 → 39자). 카드 면에는 숫자판만 있고 문장은 폭 240 말풍선(13px)에 들어가니, 최장 카드도 3줄 안팎으로 추정해요. 옮기는 과정에서 **문구가 코드 동작과 다른 카드 2장**(함께 외치기, 담금질 유리)과 **틀린 설명 1개**(뿌리내리기 "HP가 가장 낮은")가 드러났어요(5장).

### 2.6 조사·숫자 표기 근거 (스타일 가이드·규범)

- **Microsoft 한국어 현지화 스타일 가이드**: "~하세요"·"~합니다"로 끝나는 문장은 영어 원문 부호와 상관없이 **마침표**로 끝내요(4.1.10). 자리표시자 뒤에는 `은(는)`, `이(가)`, `을(를)`, `과(와)`, `(으)로`처럼 **두 조사를 함께** 쓰라고 해요. 숫자 자리표시자 뒤에는 단위(`%d자`, `%d개`, `%d일`)를 **붙여** 쓰라고 해요. 안내문 어미는 "~십시오"보다 "~세요"를 권해요. 출처: https://download.microsoft.com/download/5/b/6/5b62389f-4e3b-4c77-bc18-94efba2fa7bb/kor-kor-StyleGuide.pdf
  - 소프트웨어 오류 메시지용 규칙이에요. 게임 카드 데이터 4종에서는 `을(를)`이 **0건**이라, 게임은 병기 대신 문장을 조사가 필요 없게 짜거나 받침을 계산한 것으로 보여요(필자 해석).
- **한글 맞춤법 제43항**: 단위 명사는 띄어 쓰지만, "숫자와 어울리어 쓰이는 경우에는 붙여 쓸 수 있다". `1장`, `2턴`, `3번`을 붙여 쓰는 근거예요. 출처: https://korean.go.kr/kornorms/regltn/regltnView.do?regltn_code=0001&regltn_no=200
- **변수 뒤 조사 자동 선택**: i18next 후처리기로 `[[를]]`처럼 조사를 하나만 쓰면 앞 글자 받침을 보고 고르는 방식, 숫자는 **한국어 발음**으로 판단한다는 설명(3 → 삼 → 받침 있음, 2 → 이 → 받침 없음). `설명를` 같은 하드코딩 실패와 `을/를` 노출이 비전문적으로 보인다는 문제도 짚어요. 출처: https://velog.io/@sumi-0011/i18n-post-korea
- **하스스톤 디자이너의 문구 원칙**: 카드 문구에서 가장 중요한 건 "reads naturally and makes sense to as many players as possible"이라고 했고, 같은 카드 하나를 4명이 30분 동안 템플릿 잡았다는 답글도 있어요. 사소한 불일치는 감수한다고도 했어요. 출처: https://outof.games/devtracker/hearthstone/twitter/twitter-hearthstone/27329 (약 4년 전 게시)

## 3. 규칙 초안

**기본 틀** (모든 효과문)

```
[시점·조건절], [대상]에게 [대상물]을/를 [수][단위] [동사]합니다.
```

변형 둘:

```
받는 쪽이 주어:  [대상]이/가 [대상물]을/를 [수] 얻습니다/입습니다.
수치 변화:       [대상]의 [수치]이/가 [수] 늘어납니다/줄어듭니다/오릅니다.
```

조사는 고정 낱말(피해, 방어도, 화상…) 뒤에만 오고, **숫자 뒤에는 오지 않게** 짜요(R13).

### R1. 어미는 합니다체 평서문

- 규칙: 효과문, 용어 풀이, 적 의도 풀이, 패시브, 이벤트 결과는 모두 "~합니다."로 끝내요. 예외는 둘이에요. 카드 성질 한 단어 문장(`소멸.` `지속.`, R9)과 트리거 꼬리표(`연속 2:`, R9).
- 좋은 예: `피해를 10 입힙니다.`
- 나쁜 예: `피해 10.` / `피해 10을 줘요.` / `피해 10점을 입힌다.`
- 근거: 합니다로 끝난 문장이 하스스톤 9,141 : 한다 0, 룬테라 302 : 0, StS2 130 : 0이에요(2.1). 명사 끝(섀도우버스)과 한다체(MTG)는 소수 관행이에요.

### R2. 문장 틀과 어순

- 규칙: [시점·조건] → [대상] → [대상물+조사] → [수+단위] → [동사] 순서예요. 대상이 기본값(단일 적·자기 자신)이면 대상 칸을 비워요(R6).
- 좋은 예: `내 턴 시작 시, 방어도를 5 얻습니다.` / `모든 적에게 화상을 3 부여합니다.`
- 나쁜 예: `방어도 5를 내 턴 시작 시 얻습니다.` (시점이 뒤로 감) / `5의 방어도를 얻습니다.` (숫자가 앞으로 감)
- 근거: 고정 수치는 하스스톤 896장·StS2 37장·룬테라 29장이 모두 `피해를 N 동사`예요(2.2). StS2 트리거 문장도 `내 턴 시작 시, 힘을 3 얻습니다.`처럼 시점이 맨 앞이에요.

### R3. 효과별 동사

| 효과 | 동사 | 틀 | 근거 |
| --- | --- | --- | --- |
| 피해 (주는 쪽) | 입히다 | `피해를 N 입힙니다.` | Lucy 결정. 룬테라 31 : 1 |
| 피해 (받는 쪽 주어) | 입다 | `모든 정령이 피해를 N 입습니다.` | 룬테라 `모든 유닛이 피해를 1 입습니다.` |
| 방어도·반격·도발·마력 (자기 자신) | 얻다 | `방어도를 N 얻습니다.` | StS2 `X를 N 얻습니다` 20장 |
| 방어도 (다른 아군에게) | 주다 | `아군 하나에게 방어도를 N 줍니다.` | 정본 말풍선 `방어도 5를 줘요` |
| 상태 (화상·냉기·취약·약화·강화) | 부여하다 | `화상을 N 부여합니다.` | StS2 16장, 하스스톤 122장 |
| 회복 | 회복하다 | `HP를 N 회복합니다.` | StS `체력을 6 회복합니다` (하스스톤·룬테라는 `회복시킵니다`) |
| 카드 뽑기 | 뽑다 | `카드를 N장 뽑습니다.` | StS·하스스톤·룬테라 공통 |
| 배수 | ~배로 늘리다 | `대상의 화상을 2배로 늘립니다.` | StS `힘이 2배로 증가합니다`가 음수에서 오해된 사례(2.7) |
| 비율 수치 | 오르다 | `싱크로율이 N%p 오릅니다.` | 성격 "명랑" 현행 문구 `올라요` |
| 비용 변경 | ~이/가 되다, 줄어들다 | `비용이 0이 됩니다.` | StS1 `스킬 카드의 비용이 0이 됩니다.` |

- 나쁜 예: `피해를 10 가합니다.` (0건) / `화상을 3 겁니다.` (같은 상태 부여를 카드마다 다른 동사로)

### R4. 숫자

- 규칙: (a) 숫자는 대상물 조사 뒤, 동사 앞에 두고 띄어 써요(`피해를 6 입힙니다`). (b) `N의 X`는 쓰지 않아요. (c) 단위는 붙여요(`1장`, `2턴`, `3번`, `10%p`). (d) 문장 안에서는 `+`를 붙이지 않아요. `+N`은 숫자판·떠오르는 숫자·로그용이에요. (e) 화면에는 능력치를 반영한 **최종 수치**를 써요(R12).
- 좋은 예: `카드를 1장 뽑습니다.` / `다음 턴에 마력을 1 더 얻습니다.`
- 나쁜 예: `1장의 카드를 뽑습니다.` / `1의 마력을 얻습니다.` / `마력을 +1 얻습니다.` / `피해를 2 만큼 4 번`
- 근거: StS1 유물의 `N의` 꼴 혼재(5/25)와 그에 대한 불만(2.2, 2.7), StS2의 `N의` 꼴 0건, 맞춤법 제43항 단서와 MS 가이드의 "단위 붙여 쓰기"(2.6).

### R5. 다단 히트

- 규칙: `피해를 N씩 M번 입힙니다.` 대상구는 앞에 붙여요(`모든 적에게 피해를 N씩 M번 입힙니다.`).
- 좋은 예: `피해를 3씩 2번 입힙니다.`
- 나쁜 예: `피해 3을 2번` (조사가 숫자 뒤에 와서 수치가 2·4·5·9면 틀림, R13) / `피해를 3 × 2 입힙니다.`
- 근거: StS는 `N만큼 M번`(StS2 5장)이에요. 이 문서는 `씩`을 권해요. "만큼"은 `현재 방어도만큼`, `화상 수치만큼`처럼 **변하는 양**에 이미 쓰고 있어서, 고정 수치까지 "만큼"으로 쓰면 한 글자 차이로 뜻이 갈려요(필자 판단). `씩`은 하스스톤에서 여러 대상에 "각각"의 뜻으로 40장에 쓰여 자연스러운 꼴이에요.

### R6. 대상

| 대상 | 쓰는 꼴 | 근거 |
| --- | --- | --- |
| 적 하나 (끌어서 고름) | 생략 | StS 단일 대상 피해 카드는 모두 생략(`피해를 6 줍니다.`) |
| 적 전체 | `모든 적에게` | StS2 13장(1편 `적 전체에게`에서 바뀜), 하스스톤 109장 |
| 앞서 고른 적을 다시 가리킴 | `대상` | StS2 `대상 적에게`, `대상 적이 ~` |
| 자기 자신 (카드 주인 정령) | 생략. 다른 대상과 섞이면 `이 정령이` | StS `방어도를 5 얻습니다.` |
| 아군 하나 | `아군 하나에게` / `아군 하나의` | 룬테라 `아군 하나에게`, 정본 말풍선 |
| 아군 전체 | `모든 아군이` / `모든 아군의` | 룬테라 `모든 아군에게` |
| 앞열 | `앞열 정령에게` | Lucy 용어 "앞열" |

- 규칙: 대상은 **효과마다** 붙여요. 카드 전체 앞에 접두어 하나를 다는 지금 방식(`TARGET_PREFIX`)은 효과마다 대상이 다를 때 틀려요. 예: 담금질 유리 `아군 전체 방어도 5, 반격 2`는 반격도 모두가 받는 것처럼 읽히지만, 코드에서 반격은 카드 주인만 받아요(5장 O7).
- 좋은 예: `모든 아군이 방어도를 5 얻습니다. 이 정령이 반격을 2 얻습니다.`
- 나쁜 예: `아군 전체 방어도 5, 반격 2` / `아군 1 회복 4`

### R7. 조건·트리거

- 규칙:
  1. 조건절은 **문장 맨 앞**에 두고 뒤에 **쉼표**를 찍어요.
  2. 조건 문장은 **기본 효과 문장 뒤**에 와요.
  3. 꼴은 셋으로 나눠요. 상태 조건은 `[대상]이 [상태] 상태이면,`, 되풀이되는 사건은 `~할 때마다,`, 시점은 `내 턴 시작 시,` · `내 턴이 끝날 때,` · `매 전투 시작 시,`예요. 한 번 일어나는 사건은 `~하면,`이에요.
  4. "~경우"는 쓰지 않아요.
- 좋은 예: `피해를 8 입힙니다. 대상이 화상 상태이면, 한 번 더 입힙니다.`
- 나쁜 예: `대상이 화상이면 한 번 더` (서술어 없음, "화상"만으로 상태인지 카드인지 흐림) / `대상이 화상 상태인 경우 피해를 추가로 입힙니다.`
- 근거: 조건 문장이 기본 효과 뒤에 오는 비율이 하스스톤 459 : 47, StS2 8 : 0이에요. 쉼표는 하스스톤 `~면,` 860 : 297, 섀도우버스 1,529 : 78, StS2 13 : 1이에요. "~경우"는 많아야 1% 안팎이에요(2.4). `상태이면`은 하스스톤의 격노 풀어쓰기와 같은 꼴이에요.
- 참고: Lucy 예시 `대상이 화상 상태이면 피해를 추가로 10 입힙니다.`도 틀은 같아요. 다만 맞불은 피해를 **한 번 더 따로** 넣어서(취약·방어도 계산을 다시 함) "추가로 10"으로 쓰면 한 번에 20이 들어가는 것처럼 읽힐 수 있어요. 고르는 건 5장 O4에 두었어요. 쉼표를 짧은 조건에도 찍을지는 O10이에요.

### R8. 기간

- 규칙: `이번 턴에`는 시점·횟수(`이번 턴에 다음으로 사용하는 카드`), `이번 턴 동안`은 이어지는 상태(`이번 턴 동안 입히는 피해가 3 늘어납니다`), `이번 전투 동안`은 전투 내내, `다음 턴에`는 한 번 일어나는 일이에요. 턴 수로 지속되는 상태(취약·약화)는 숫자에 단위 `턴`을 붙여요(`취약을 2턴 부여합니다`, O1).
- 좋은 예: `다음 턴에 마력을 1 더 얻습니다.`
- 나쁜 예: `다음 턴 마력 +1` / `이번 턴 다음에 쓰는 …`
- 근거: StS2에서 `이번 턴에` 8 · `이번 턴 동안` 7장이 이 구분대로 쓰여요. 하스스톤은 `이번 턴에` 342 : `동안` 4로 거의 "에"만 써요(2.3).

### R9. 키워드·카드 성질·트리거 꼬리표

- 규칙:
  1. 고정 용어는 표기를 바꾸지 않고, 풀이가 있는 용어는 점선 밑줄로 표시해요(정본 관행, `CLIENT_HANDOFF` 6절).
  2. 카드 성질은 명사 + 마침표 한 단어 문장이에요. `지속.`은 맨 앞, `소멸.`은 맨 끝에 와요.
  3. 조건부 발동 묶음은 `연속 N:` 꼬리표 + 완결된 문장이에요.
- 좋은 예: `지속. 내 턴 시작 시, 방어도를 5 얻습니다.` / `… 소멸.` / `연속 2: 피해를 3씩 2번 입힙니다.`
- 나쁜 예: `…, 소멸` (마침표 없이 쉼표 뒤) / `연속 2: 피해 3을 2번`
- 근거: StS1·StS2의 `소멸.` 14번 모두 맨 끝(StS1 `휘발성.`도 끝), `선천성.`(3) `교활.`(1) `보존.`(1) 맨 앞(1.1, 1.2). 손에 있을 때의 성질은 앞, 사용 뒤의 처리는 끝이라는 갈래로 읽혀요(필자 해석). 하스스톤은 꼬리표 + 콜론 + 문장 꼴이 흔하고(`연계:`, `전투의 함성:`, `비밀:`), 룬테라는 `공격:`, `라운드 종료:`를 써요.

### R10. 한 카드에 여러 효과

- 규칙: 효과마다 한 문장이고, **실제 처리 순서**대로 써요. 같은 대상구(`모든 적에게`)가 두 번 나올 때만 앞 효과를 "~고"로 이어 대상구를 한 번만 써요. 효과문은 2문장 이하를 목표로 하고, 3문장을 넘기지 않아요.
- 좋은 예: `모든 적에게 피해를 5 입히고 화상을 3 부여합니다.` / `피해를 3 입힙니다. 화상을 3 부여합니다.`
- 나쁜 예: `모든 적에게 피해를 5 입힙니다. 모든 적에게 화상을 3 부여합니다.` / `피해 3, 화상 3`
- 근거: StS2 천둥·아지랑이가 "~고"로 이어요. 단일 대상 카드는 `피해를 6 줍니다. 중독을 3 부여합니다.`처럼 나눠요. 2문장 이하인 카드가 StS2 79장 중 75장, 하스스톤 98%예요(2.1).

### R11. 문장부호

- 규칙: 모든 문장은 마침표로 끝내요. 괄호 보충 설명 대신 문장을 하나 더 써요. `×`, `→`, `!`는 효과문에 쓰지 않아요(계산 줄·로그·떠오르는 숫자에서만 써요).
- 좋은 예: `현재 방어도만큼 피해를 입힙니다. 파워의 영향을 받지 않습니다.`
- 나쁜 예: `현재 방어도만큼 피해 (파워 보정 없음)` / `회복 5 → 화상 8 역류!`
- 근거: 마침표로 끝나는 카드가 룬테라·StS 100%, 하스스톤 95.6%예요(마침표 없는 건 `도발` 같은 키워드뿐). MS 가이드도 합니다 문장은 마침표로 끝내라고 해요(2.6).

### R12. 변하는 수치

- 규칙: 문장에는 시전 정령 능력치까지 반영한 최종 수치를 써요. 기본값보다 오르거나 내린 건 숫자 색·▲ 표식으로 보이고(0011·0019), 계산식은 말풍선 계산 줄(정본 `기본 7 + 파워 2 = 9`)로 보여요. "1장당" 효과는 문장에 **장당 수치**를 쓰고 지금 합계는 계산 줄에 둬요.
- 좋은 예: `이번 전투에서 사용한 불 카드 1장당 피해를 2 입힙니다.` (계산 줄 `불 카드 4장 × 2 = 8`)
- 나쁜 예: `이번 전투에서 쓴 불 카드 1장당 피해 2×파워`
- 근거: StS2 달의 세례 `이번 턴에 사용한 스킬 카드 1장당 피해를 4 줍니다.`가 같은 틀이에요. 카드 동사 "사용"(0011)과도 글자가 같아요.

### R13. 조사 처리

- 규칙:
  1. 틀은 숫자 뒤에 조사가 오지 않게 짜요.
  2. 고정 용어의 조사는 표로 미리 정해 둬요(아래).
  3. 정령 이름·카드 이름 같은 변수 뒤 조사는 받침을 계산하는 함수로 붙이고, `을(를)` 병기는 화면에 내보내지 않아요.
  4. 숫자 뒤 조사가 피할 수 없을 때는 한국어 발음으로 받침을 판단해요. 받침 있음: 0(영)·1(일)·3(삼)·6(육)·7(칠)·8(팔)·10(십). 받침 없음: 2(이)·4(사)·5(오)·9(구). 100(백)·1000(천)은 받침 있음, 끝자리가 0인 수는 마지막 자리 읽기로 판단해요.
- 좋은 예: `피해를 2씩 3번 입힙니다.` (숫자 뒤 조사 없음) / `{정령}이(가)` 대신 함수로 `불여우가`
- 나쁜 예: 현행 `${d}을 ${op.hits}번`은 d가 2·4·5·9면 `피해 2을 2번`이 돼요. `약화을(를) 1 부여합니다`(op.gg)
- 근거: 공식 카드 데이터 4종에서 `을(를)` 0건, 2차 사이트의 실패 사례(1.2), MS 가이드의 병기 규칙(오류 메시지용), velog의 숫자 발음 판단(2.6).

### R14. 용어 풀이 (툴팁)

- 규칙: 제목은 용어 이름, 본문은 합니다체 1~2문장, 공백 빼고 40자 안팎이에요. 첫 문장은 **무엇이 일어나는지**, 둘째 문장은 **언제 줄거나 사라지는지**예요. 주어(상태가 걸린 쪽)는 생략하고, 바뀔 수 있는 수치(취약 %)는 변수로 넣어요.
- 좋은 예: `화상 | 자기 턴이 끝날 때 화상 수치만큼 피해를 입습니다. 그 뒤 화상이 1 줄어듭니다.`
- 나쁜 예: `화상: 턴 끝 피해, 1 감소` / `화상 상태가 되면 매 턴이 끝날 때마다 화상 수치만큼의 피해를 받게 되며 …` (길고 수동)
- 근거: 룬테라 123개 중 120개 합니다체, 중앙값 32자, 1~2문장이 95%(2.5). 0019 원칙 3("용어 풀이는 짧게").

### R15. 적 의도

- 규칙: 판 위 의도는 아이콘 + 숫자로 보이고 문장을 쓰지 않아요(0007·0019). 호버 풀이는 합니다체 문장으로 쓰고, 행동 주체(그 적)는 생략하고 **대상은 꼭 밝혀요.**
- 좋은 예: `앞열 정령에게 피해를 7씩 2번 입힙니다. 방어도를 무시합니다.`
- 나쁜 예: `앞열 피해 7×2 (방어 무시)`
- 근거: StS2 몬스터 행동 풀이가 카드와 같은 합니다체 틀이에요(`피해를 8 줍니다. 모든 플레이어에게 …를 1 부여합니다.`, 1.2). 판 위 숫자·기호는 0019 원칙 1이에요.

### R16. 패시브 (성격·지속·유물류)

- 규칙: `[트리거], [효과]합니다.` 능력치 성격은 `[능력치]이/가 N% 높습니다.`, 횟수 제한은 마지막 문장 `턴마다 한 번만 발동합니다.`로 써요.
- 좋은 예: `HP가 절반 이하이면 파워가 30% 높아집니다.` / `매 전투 시작 시, 모든 적에게 취약을 1 부여합니다.`
- 나쁜 예: `… 이번 턴 비용 -1.` / `턴당 1번.`
- 근거: StS2 유물 `매 전투 시작 시, …`(2/2), StS1 유물 25개 모두 합니다체, 룬테라 잠복 `라운드당 한 번만 발동합니다.`

### R17. 이벤트 결과

- 규칙: 결과마다 합니다체 한 문장으로 쓰고, 얻는 건 `[무엇]을 N 얻습니다.`, 잃거나 다치는 건 받는 쪽을 주어로 써요.
- 좋은 예: `골드를 40 얻습니다. 모든 정령이 피해를 3 입습니다.`
- 나쁜 예: `골드 +40, 모든 정령 피해 3`
- 근거: 룬테라 `모든 유닛이 피해를 1 입습니다.` 다만 이벤트 결과는 고를 때 쓰는 "판단 정보"이기도 해서, 0019 원칙 1과 부딪쳐요(O5).

### R18. 같은 개념은 한 단어로

- 규칙: 카드를 내는 동작은 "사용"(0011)이에요(현행 문구의 "쓰는"을 바꿔요). 같은 상태를 거는 동작은 언제나 "부여"이고, 같은 대상 표현은 R6 표 하나만 써요.
- 근거: 0.9 불만의 핵심이 "통일 안 됨"이에요. 하스스톤 디자이너도 "from your deck" 유무 같은 불일치를 지적받았어요(2.6).

## 5. 열린 문제

### O1. 취약·약화의 턴 수를 어떻게 쓸까

| 안 | 예 | 장점 | 단점 |
| --- | --- | --- | --- |
| A. 숫자만 (StS) | `취약을 2 부여합니다.` | 가장 짧음, StS와 같음 | 숫자가 세기인지 턴인지 풀이를 봐야 앎 |
| B. 숫자 + 턴 | `취약을 2턴 부여합니다.` | 틀(R2)을 지키면서 뜻이 바로 보임. 한 글자 더 | "2턴을 부여"가 살짝 어색하다는 사람이 있을 수 있음 |
| C. 기간 부사 | `2턴 동안 취약하게 만듭니다.` | 문법이 가장 자연스러움 | 틀이 깨지고, "취약"이 상태명에서 형용사로 바뀜 |

**추천: B.** 현행 문구(`취약 2턴`)와 떠오르는 숫자(`취약 2`)를 그대로 잇고, MS 가이드의 "숫자 뒤 단위" 원칙과도 맞아요.

### O2. 단일 적 대상을 생략할까

| 안 | 예 | 근거 |
| --- | --- | --- |
| A. 생략 | `피해를 6 입힙니다.` | StS 전부. 끌어서 대상을 고르니 문장에 없어도 됨. 가장 짧음 |
| B. `적 하나에게` | `적 하나에게 피해를 6 입힙니다.` | 정본 말풍선(`적 하나에게 피해 9를 줘요.`), 룬테라 |

**추천: A.** 대상이 다른 카드(전체·아군)만 대상구가 붙어서 오히려 눈에 띄어요. 정본 말풍선 문구를 고칠 때 같이 정해야 해요.

### O3. 점화를 풀어 쓸까, 키워드로 둘까

| 안 | 예 | 길이 |
| --- | --- | --- |
| A. 풀어 쓰기 | `화상 수치만큼 피해를 입히고 화상을 모두 없앱니다.` | 22자 (불사의 숨결 39자) |
| B. 키워드 문장 | `점화.` + 풀이 `대상의 화상을 모두 터뜨려 그만큼 피해를 입힙니다.` | 2자 |
| C. 동사형 | `화상을 점화합니다.` + 풀이 | 7자 |

**추천: 결정 대기.** 0018이 "점화"를 예약어로 두었고 0008의 기믹 이름이기도 해요. 키워드로 쓰는지가 먼저 정해져야 해요. 키워드라면 B, 아직 아니면 A예요. 하스스톤 "격노" 사례(2.4)처럼 쓰는 카드가 2장뿐이면 풀어 쓰는 쪽이 이해하기 쉬울 수 있어요.

### O5. 이벤트 결과를 문장으로 쓸까

### O6. 한 화면 안의 문체 섞임

지금 성격·이벤트 본문·정본 말풍선은 해요체예요(`가드가 15% 높아요.`, `샘물이 솟아요.`, `적 하나에게 피해 9를 줘요.`). 효과문만 합니다체로 바꾸면 이벤트 화면에서 본문은 해요체, 결과는 합니다체가 돼요.

| 안 | 내용 |
| --- | --- |
| A. 갈래로 나눔 | **규칙 서술**(효과·용어 풀이·결과·성격)은 합니다체, **이야기·안내**(이벤트 본문, 대사, 토스트, 버튼 안내)는 해요체 |
| B. 전부 합니다체 | 이벤트 본문까지 합니다체 |
| C. 전부 해요체 | Lucy 방향과 어긋나서 제외 |

**추천: A.** 하스스톤도 카드 문구(합니다)와 대사·안내 문구를 다르게 쓰고, MS 가이드도 안내문은 "~세요"를 권해요. "규칙은 딱딱하게, 세계는 다정하게"로 갈래가 분명하면 섞여도 의도로 읽혀요. 정본 말풍선 문구(`canonRest` 고정 데이터)는 이 결정 뒤에 바꿔야 해요.

### O7. 문구와 코드 동작이 다른 카드

| 카드 | 현재 문구가 말하는 것 | 코드가 하는 것 |

| 담금질 유리 (target `allAllies`, `block` 5 + `thorns` 2) | 아군 전체가 방어도와 반격을 받음 | 방어도는 전체, **반격은 주인만** |

- 안: A. 코드를 문구에 맞춤(기획 의도가 "아군 전체"라면). B. 문구를 코드에 맞춤(4.2의 제안 문구). C. 카드 데이터에 효과별 대상을 넣어 둘 다 표현.
- **추천: 의도 확인 후 A 또는 B. 장기적으로는 C.** StS 유물 불만의 대부분이 "설명 ≠ 동작"이었어요(2.7). `src/core`를 바꾸면 골든 스냅샷이 바뀌니 별도 PR이 필요해요.

## 부록: 구현 메모 (참고, 코드 수정 아님)

- 효과별 문장 틀을 표 하나로 두고 `describeCard`가 표를 채우는 구조로 바꾸면 R18(통일)을 코드가 지켜요. 하스스톤 디자이너가 말한 "템플릿 잡기"를 데이터로 굳히는 셈이에요.
- 조사: 고정 용어는 R13 표처럼 조사를 미리 붙인 꼴로 저장하고, 변수 이름 뒤에만 받침 계산 함수(`josa(name, "을/를")`)를 써요. 숫자 뒤에 조사가 오는 틀은 만들지 않아요. 필요하면 발음표(R13-4)로 판단해요.
- 시험: 효과마다 수치 0·1·2·3·4·5·9·10·11·20을 넣은 문구 스냅샷을 두면 `2을` 같은 조사 실패가 테스트에서 잡혀요.
