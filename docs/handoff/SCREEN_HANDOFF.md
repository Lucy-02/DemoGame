# 화면 작업 인수인계 (런 밖 여정 스레드용)

작성: 2026-11-11 · 쓴 곳: 전투 결과·상점·런 화면 스레드 · 읽는 곳: 나머지 유저 여정 화면을 기획·디자인·구현할 새 스레드

전투 결과와 상점을 시안에서 코드까지 옮기면서 배운 것을 모았어요. `CLIENT_HANDOFF.md`(전투 화면·렌더링 디테일)와 겹치는 내용은 다시 적지 않고 가리키기만 해요. 이 문서의 화면 나눔과 순서는 제안이에요. Lucy가 정해요.

| 스레드 | 맡는 화면 | 지금 상태 |
|---|---|---|
| 런 안 (기존) | 전투, 전투 결과, 상점, 런 결과, 휴식, 이벤트, 탐험 중 정령 보기, 덱 보기·카드 빼기 | 전투 결과와 상점은 런에 연결됨(레거시 `RewardScene`·`ShopScene` 삭제). 나머지는 시안 `0046` |
| 런 밖 (새 스레드) | 타이틀, 첫 시작(온보딩), 정원 허브, 출전 준비, 갈래 고르기·진화 연출 연결, 일시정지·포기, 설정, 도감·기록, 해금 알림 | 묶음 B 정리안 `0047`이 **페르소나 컨펌, Lucy 확인 대기**. 구현은 정령 관리(`src/presentation/spirits`)만 있음 |

### 2-2. 레퍼런스 게임 연구
런 밖 여정(타이틀 → 첫 실행 → 거점 → 출전 준비 → 런 → 런 종료 → 해금 → 거점)을 레퍼런스 게임이 어떻게 푸는지 화면 단위로 조사해요.
- 덱빌더·로그라이트: Slay the Spire(1·2), Monster Train(1·2), Balatro, Inscryption, Wildfrost, Cobalt Core, Across the Obelisk
- 키우는 대상이 있는 거점형: Hades(1·2), Darkest Dungeon, Cult of the Lamb, Loop Hero, Dave the Diver
- 수집·육성: 포켓몬, Cassette Beasts, Monster Sanctuary, Ooblets
- 화면마다 볼 것: 첫 실행에서 첫 전투까지 걸음 수, 타이틀과 거점을 나누는지, 거점에서 할 일을 어떻게 알리는지, 출전 준비에서 고르는 것과 확인만 하는 것, 일시정지 메뉴 항목과 포기 확인, 설정 구성(접근성 포함), 도감이 무엇을 세고 무엇을 숨기는지, 해금을 언제 어디서 알리는지

### 2-4. 연구 노트 형식
- `screen-flow.md`와 같은 표기를 써요: 링크로 확인한 것은 **[출처]**, 플레이 경험·통념은 **[미검증]**.
- Lucy는 슬더슬을 하지 않았어요. 관례를 근거로 들 땐 "어떤 상황에서 나오는 어떤 결정인지"를 풀어 써요.
- 레이아웃·색·글꼴·이름은 제안하지 않고, 정보 구조와 흐름, 우리 결정과 부딪히는 곳, Lucy에게 물을 질문만 적어요.
- 웹 조사 에이전트는 Lucy 설정대로 Opus LTS로 돌려요.
- 노트는 `design/concepts/`에 두고, 끝나면 `screen-flow.md`의 낡은 표를 고쳐요.

## 3. 디자인 라운드에서 배운 것

- **브리프보다 장부가 먼저예요.** 시안이 Lucy가 고른 조각을 말없이 빼면 그 라운드는 버려져요. 시안 머리에 "장부와 달라진 점"을 적게 해요.
- **한 아티팩트에 여러 화면, 꽉 찬 상황까지.** 화면 하나씩 정하면 일관성(같은 정보는 같은 자리)이 깨져요. 묶음 A·B처럼 여정 순서로 묶어요.
- **Lucy가 버린 것** (다시 내지 않아요): 화면 제목("승리"), 아래에서 올라오는 넓은 판, 웹서비스 같은 라벨·설명 문장, 의미색 채움(표지로만), 한쪽 두꺼운 테두리, 억지 장식 도형, 기호 타일 배지, 화면 안 제작 메모, 줄 맞춤 보상(E2), 사물과 진열(V2).
- **Lucy가 고른 것**: 정령 세 줄이 뼈대, 늘 보이는 글자는 이름·숫자·버튼 동사, 설명은 호버, 크기는 관심사와 여정 순서, 결과 숫자보다 원인(능력치), a→b 미리보기, 정본 기호 세트와 큰 숫자.
- **페르소나 컨펌은 Lucy 확인이 아니에요.** `design-director-proxy`가 고른 것은 ⏳로 남기고, Lucy가 보면 ✅로 바꿔요. `0047`이 지금 이 상태예요.
- **시안 값은 임시예요.** 구현할 때 `tokens.provisional`에 넣고, Lucy가 고른 뒤에만 정식 토큰으로 올려요. 없는 값은 `TODO_TOKEN`, 없는 기호는 `TODO_ICON`, 없는 이름은 `TODO_NAME`.
- **규칙이 화면보다 먼저 흔들려요.** 전투 결과는 보상 규칙(0049)이 바뀌어 두 번 다시 그렸어요. 화면이 기대는 규칙이 열려 있으면 먼저 Lucy에게 묻고, 규칙 구현은 따로 맡겨요(UI 작업은 `src/core`·`src/data`를 건드리지 않아요).
- **낱말은 따로 확인받아요.** `층`, `카드 빼기`, `떠나기`, `탐험 포기`, `갈래 · 자람 · 결과`는 아직 임시예요.
- 답은 짧게, 선택지는 2~3개에 추천 하나, 근거 한 줄. 캡처를 붙이면 Lucy가 빨리 골라요.

## 4. 구현에서 배운 것

### 4-1. 화면 하나의 뼈대
`src/presentation/result/`, `shop/`이 본보기예요. 화면마다 같은 파일을 둬요.

| 파일 | 일 |
|---|---|
| `viewmodel.ts` | 화면이 그리는 값만 담은 VM. core 타입을 넣지 않아요 |
| `fixtures.ts` | 고정 장면. `?screen=이름&scene=장면`으로 열어요. 시안의 프레임마다 하나 |
| `from*.ts` | 세션 → VM 변환 |
| `layout.ts` | 자리·크기(토큰 조합). 리터럴은 여기서도 못 써요(`design/strict-paths.txt`) |
| `copy.ts` | 화면 글자 |
| `*Scene.ts` | 상태(hover·held·taken)와 입력. 그리기는 `views/` |

- **다시 그리기 방식**: 상태가 바뀌면 `dirty = true`, `update()`에서 전부 지우고 다시 그려요. 입력은 `this.input.setPollAlways()`. 화면이 작아서 충분히 빠르고, 상태별 캡처가 쉬워요.
- **세션**: `src/session/`에 화면마다 하나(`RewardSession`, `ShopSession`). 명령을 받아 `Run`을 바꾸고, 화면은 세션만 알아요. 세션 없이 고정 장면으로도 열려야 해요.
- **런 연결**: 지금 끝까지 플레이되는 것은 레거시(`?screen=legacy`)뿐이라, 새 씬을 레거시 `Phaser.Game`의 씬 목록에 넣고 레거시 씬이 `scene.start(새_씬, { session, onDone })`으로 열어요. 연결한 PR에서 같은 일을 하던 레거시 씬을 지워요. 레거시 캔버스는 1280×800으로 맞춰 뒀어요.
- **공용 뼈대** `src/presentation/run/`: `drawLane`(정령 줄: 얼굴 링·HP·능력치·카드 칸, 상태는 `LaneState`), `drawGold`, `drawBackdrop`, `cardWithFace`, `drawCardTip`, `fromCore.ts`(`cardVM`, `lane`, `statOf`). 런 밖 화면에서 정령 줄이 필요하면 이것부터 봐요.
- **재사용 먼저**: 카드는 `createHandCard`(`scale` 옵션은 글자·기호를 다시 또렷하게 구워요), 얼굴은 `faceTexture`·`ringTexture`, 유리판·배지는 `spirits/views/parts.ts`, 배치는 `style/flex.ts`. 시안 HTML을 옮기지 않아요(Lucy 2026-11-09).

### 4-2. 자주 걸린 곳
- 토큰을 맨 문자열로 넣으면 생성되지 않아요. `{ "$value": … }` 꼴로 넣고 `pnpm tokens`.
- 카드를 확대하면 흐려져요. `scale` 옵션과 미리 구운 얼굴 텍스처를 써요.
- 씬을 연 직후(preload 중)의 클릭은 먹지 않아요. 자동 확인에서는 잠깐 기다린 뒤 눌러요.
- 이름이 없는 것(바람 재료 등)이 화면에 `TODO_NAME`으로 그대로 찍혔어요. 빈 값은 그리기 전에 걸러요.
- 시간 값은 지어내지 않아요. 그래서 전투 결과는 고르면 바로 지도로 넘어가요. 머무는 시간·전환은 Lucy가 정할 값이에요.
- 카드 id는 `src/data`에서 찾아 써요(추측하면 틀려요).
- 글자·도형·묶음의 Phaser 4 렌더링 디테일은 `CLIENT_HANDOFF.md` 6절에 있어요.

### 4-3. 눈으로 확인하기
- `pnpm dev:web --port 5199` 뒤 Playwright로 `canvas` 요소를 찍어요(페이지 전체를 찍으면 개발 창 틀 때문에 어긋나요). 1280×800으로 잘라 시안 프레임과 겹쳐 봐요.
- 스크립트: `/mnt/project-files/handoff/screen-tools/` (`shot.cjs` 상태별 캡처, `flow.cjs` 클릭 흐름, `legacy.cjs` 레거시 게임 안에서 새 씬 열어 런 값 확인, `dump.cjs` 시안 HTML에서 프레임의 자리·크기 뽑기).
- 공용 컴포넌트를 바꿨으면 전투·정령 관리 화면도 다시 찍어 비교해요.
- PR 전에 `pnpm check`. Lucy에게는 캡처를 `/mnt/project-files/design/<화면>-impl/`에 두고 보여 줘요.
