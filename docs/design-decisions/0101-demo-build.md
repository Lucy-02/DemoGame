# 0101. 데모 빌드: 패키징 확인, 데모 범위 스위치, 데모 끝 화면

- 라운드: 프로젝트 스레드 "데모 빌드 만들기"

- 앞 결정: 0099 2번, 0084 4 · 9번 (창 크기 · 오류 기록), 0090 (설정), 0046 (판 결과 틀), 0053 (시작 풀 · 깃들기)

## 결정
1. **데모 스위치는 빌드 모드 하나예요.** `pnpm dist:demo`(= `electron-vite build --mode demo`, `.env.demo`의 `VITE_DEMO=1`)가 `release/demo/`에 만들어요. 개발 서버에서는 `?demo`로 켜요.
2. **데모 범위**: `constants.demo.acts`(2)막까지. 게임이 여는 막(`acts_enabled`)을 넘지 않아요. 정령은 시작 풀 넷, 깃들기는 두 번(첫 판 뒤 · 첫 보스 뒤)으로 지금 규칙 그대로예요. 시작 풀이 늘면 시험이 알려 줘요(`session/game.test.ts`).
3. **데모 끝 화면**: 데모에서 마지막 막의 보스를 이긴 판 결과 다음에 떠요. 판 결과의 어느 버튼을 눌러도 거치고, 버튼 하나가 그 버튼이 가던 곳(정원으로 · 다시 떠나기)으로 이어 가요. 판 결과 틀(배경 · 왼쪽 열 · 버튼 자리)을 그대로 쓰고, 제목 `데모 끝` + 점선 빈칸 둘(`[위시리스트]` · `[피드백]`)이에요. 링크 주소 · 낱말 · 스팀 페이지 · 이름 · 로고는 넣지 않았어요.
4. **버전 표시**: 데모는 `v0.1.0-demo`로 메인 화면 구석과 오류 기록에 적혀요.
5. **저장은 데모와 본편이 같은 곳**을 써요(데모에서 키운 정원이 이어져요).

- 고친 것: 설정이 창을 바꾸는 동안에는 아직 안 바뀐 창 상태로 설정을 되돌리지 않아요(전체화면을 연달아 누를 때의 안전장치).

## 기각한 것과 이유
- 데모용 저장 폴더 분리: 데모에서 키운 정원을 본편이 못 읽어요.
- 데모 끝에 안내 문장: 늘 보이는 글자는 이름 · 숫자 · 버튼 동사만 (0050).

## 남은 것
- **앱 이름이 정해지면 저장 폴더 이름이 바뀌어요**(`productName`을 따라가요). 이름을 바꿀 때 폴더를 고정하거나 옮겨야 해요.
- 윈도 실행 확인, 아이콘 · 서명 · 설치 파일(지금은 폴더 묶음만).
- 화면 자동 한 판 점검(`pnpm test:run`)은 데모 범위로 돌게 바꿨는데, 휴식 두 번 눌림(0099 4번)에서 멈춰요. 그쪽이 고쳐지면 데모 끝까지 지나가요.
