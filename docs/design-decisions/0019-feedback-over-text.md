# 0019. 피드백 원칙: 바로 알 수 있는 것은 글 대신 형태·모션으로

- 날짜: 2026-10-30
- 단계: 코어 기획 / 전투 UI 원칙
- 상태: 수락됨 (Lucy, 2026-10-30 14:27). 사례별 안은 추천안 채택 (Lucy 포괄 승인 "머지하고 쭉쭉 진행해", 아래 추기)

## 맥락
전투 화면 정본 말풍선에 "마력이 모자라요 · 3 필요, 지금 2" 같은 설명 문장이 들어 있고(0007 H1의 `why` 줄), 못 내는 사유 중 마력 부족 외는 "글 띠"로 정했어요(0007). 상점·덱 화면 플레이스홀더도 토스트 문장을 써요.

## Lucy의 결정
직관적이고 바로바로 피드백이 가능한 사항은 글로 설명하지 않고 SVG·도형·아이콘·상호작용·모션으로 풀어요. 쓸데없는 설명을 텍스트화하지 않아요.

## 원칙 (정리)
1. **판단 정보**(받을 피해, 결과 미리보기, 남은 실드 칸)는 숫자·기호로 항상 보여요 — 0007 그대로.
2. **상태·이유**(못 내는 이유, 조건 미달, 기절·봉인, 돈 부족, 행동 불가)는 그 자리의 **형태·색·모션**으로 보여요. 문장을 쓰지 않아요.
3. **문장은 익히는 정보에만** 써요: 카드 효과 설명, 용어 풀이, 호버 설명. 그것도 짧게.
4. 피드백은 **그 원인이 있는 자리**에서 나와요(마력이 모자라면 마력 표시와 비용 동전이, 싱크가 모자라면 정령의 싱크 게이지가).
5. 글을 빼서 못 알아보게 되면 안 돼요. 모션·형태로 바꾼 뒤 이해도 테스트로 확인해요.

## 바뀌는 기존 결정
- 0007 "다른 사유는 글 띠" → 글 띠 대신 형태로(사례별 안은 인벤토리에서 고름).
- 0007 H1 말풍선의 `why` 문장 줄 → 삭제 또는 기호로 대체(사례별 안).
- LEDGER 정보 원칙 행에 이 원칙을 반영.
