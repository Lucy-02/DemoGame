## 구조

`src/core/battle/` 한 폴더예요. 바깥에서는 `src/core/battle`(index)만 import해요.

| 파일 | 역할 | 새 기믹을 넣을 때 |
| --- | --- | --- |
| `state.ts` | 전투 상태 타입 (`BSpirit` · `BEnemy` · `BCard` · 상태 칸 · 이벤트) | 상태 이름을 `STATUS_IDS`에 더해요 |
| `engine.ts` | `Engine` 인터페이스: 표와 핸들러가 쓸 수 있는 규칙 원시 동작 | 원시 동작이 더 필요하면 여기 선언하고 `Battle`에 구현해요 |
| `effects.ts` | 카드 효과 표 `EFFECTS`: 효과마다 처리(`resolve`) · 놓는 즉시인지(`immediate`) · 소멸 여부 · 효과문(`describe`) | 효과 하나 = 항목 하나. `types.ts`의 `CardOp`에 꼴을 더하면 컴파일이 빠진 핸들러를 잡아요 |
| `statuses.ts` | 상태 표 `STATUSES`: 쌓이는 문구 · 턴을 세는지 · 지워지는 때 · 턴 끝 처리 · 맞은 뒤 반응 | 상태 하나 = 항목 하나. 턴 끝 순서는 표 순서예요 |
| `passives.ts` | 정령에 붙어 이벤트에 반응하는 것: 지속 효과 `AURAS` · 해방 `RELEASE` · 성격 `PERSONALITY_PASSIVES`. 훅 목록은 `Passive` | 훅이 더 필요하면 `Passive`에 더하고 부르는 자리를 하나 만들어요 |
| `pipelines.ts` | 우선순위 단계 목록: 능력치 · 아군 타격 피해 · 적 공격 피해 · 적 공격 대상 · 카드 시간 · 피해 받기 | 단계를 끼우거나 순서를 바꿀 때는 목록의 `order`만 고쳐요 |
| `enemy-actions.ts` | 적 행동 표 `ENEMY_ACTIONS`: 의도 표기 · 종류 · 처리 | 행동 하나 = 항목 하나 |
| `battle.ts` | `Battle`: 상태 · 턴 흐름(턴 시작 · 턴 끝 · 라운드 끝 단계 목록) · 시간축 · 카드 놓기와 재생 · 원시 동작 구현 | 턴 흐름에 끼어드는 처리는 단계 목록에 항목으로 |

효과문은 `src/core/text.ts`가 카드 대상 문맥을 만들고, 문장은 효과 핸들러의 `describe`가 내요. 문장 조각 규칙은 `src/core/clauses.ts`예요.

## 판정 순서 (지금 값)

- 아군 타격 피해: 기본값(+성장) → 강화 → 파워 → 상성 → 치명 → 취약 → 약화 → 해방 → 허점타 → 반올림
- 적 공격 피해: 기본값 → 피해 보너스 → 약화 → 대상 취약 → 반올림
- 적 공격 대상: 전체 공격 → 도발 → 해방 도발 → 규칙(앞열 · 최저 · 무작위)
- 피해 받기: 방어도 → HP → (아군) 맞은 뒤 반응(반격)
- 카드 시간: 기본 시간 → 스피드
- 능력치: 런 기본값 → 정령에 붙은 것(용맹)
- 턴 시작: 머리 → 아군 턴 값 지우기(+지속 효과) → 적 방어도 → 시간축 → 마력 → 뽑기 → 첫 턴 훅 → 손패 훅 → 적이 건 비용 → 적이 건 봉인
- 턴 끝: 아군 상태(표 순서) + 지속 효과 → 적 상태
- 라운드 끝: 아군 상태 줄이기 · 해방 끝 → 적 상태 줄이기

2단계 기믹이 들어갈 자리: 벽은 피해 받기 앞 단계, 품기 · 디딤 · 밀물은 카드 시간 단계, 휘청은 허점타 단계, 숨음은 대상 단계(도발 앞), 별 · 받아치기는 상태 표와 훅이에요.

## 바꾸지 않은 것

- 이벤트 `BattleEvent`는 연출용 그대로예요(0001). 규칙 트리거는 `Passive` 훅과 상태 표로 하고, 연출 이벤트와 섞지 않아요.
- 상수 · 데이터 · 효과문 · 골든 스냅샷은 그대로예요.
